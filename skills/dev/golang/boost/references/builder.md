**REQUIRED BACKGROUND:** `references/start.md`, `references/fx.md`.

`github.com/xgodev/boost/inject` and `github.com/xgodev/boost/builder` generate
the wiring from comment annotations: `inject` writes one fx module per
constructor, `builder` writes the doors (REST, gRPC, MCP tool, event function), a
`Modules()` per app, the `main` of every app and the `@Middleware`
decorators; `inject` also writes the config switch of an implementation set
(`@Default`), the config registration of a settings struct (`@Config`) and
the factory clients (`*resty.Client`, redis, mongo) an `@Inject` asks for.
The app writes handlers, plain services, settings structs and annotations --
no hand-written fx module, switch module, `config.go`, factory module, door
or `main.go` for what the annotations cover.

## Canonical example (ships with boost)

- `builder/examples/simple/` -- app `api` (REST on `rest` and `admin`, gRPC
  health, the `check_stock` MCP tool on `mcp`, a `stock.Service` implemented by `stock/memory` -- `@Default`,
  `@Middleware(log, prometheus)` -- and `stock/unlimited`, chosen by
  `builder.examples.simple.stock.implementation`; `stock/memory` reads a
  `@Config Options{SoldOut []string}`) and app `worker` (cloudevents
  function); its tests boot the api with each implementation and with
  `BUILDER_EXAMPLES_SIMPLE_STOCK_MEMORY_SOLD__OUT=book,pen`, and fail when
  `gen/` or a main is stale.

## Generating

```go
//go:generate go run github.com/xgodev/boost/builder/cmd/builder --boost.builder.output=gen
```

`go generate ./...` runs inject and builder in one pass. Keys:
`boost.builder.path` (`.`), `boost.builder.output` (`gen`),
`boost.builder.cmd` (`cmd`, receives `<app>/main.go`). Output:

```
cmd/<app>/main.go                                      boost.Start() + fxfact.NewApp(<app>.Modules()...).Run()
gen/module.go                                          inject root module
gen/<import path>/<func>_module.go                     one per @Provide/@Invoke
gen/<import path>/<struct>_module.go                   one per @Config: config.Add per field + <Struct>Module()
gen/implementation/<type import path>/<type>_implementation.go   <Type>ImplementationModule(): the @Default switch
gen/client/<client type import path>/<name>_<type>.go           <Name>ClientModule(): a factory client asked by @Inject
gen/builder/<app>/modules.go                           Modules(): doors, decorators, multiserverfx.Module()
gen/builder/<app>/<server>_module.go                   one REST, gRPC or MCP server
gen/builder/<app>/function_module.go                   the @Function handler and its adapter
gen/builder/middleware/<import path>/<func>_middleware.go   Decorate<Func>(): the @Middleware decorator
```

Every generated file starts with `// Code generated by builder; DO NOT EDIT.`
(inject: `by inject`). A `cmd/<app>/main.go` without that header fails the
generation instead of being overwritten.

## Annotations

| Annotation | On | Keys |
|---|---|---|
| `@Provide` | constructor | `index` (required), `name` or `group` |
| `@Inject` | param of a `@Provide`/`@Invoke` func | `index` (required), `name` or `group` (slice param); `plugins=[a, b]` on a factory client param |
| `@Invoke` | func run on start | -- |
| `@REST` | `func(echo.Context) error`, func or method | `method`, `path` (required), `server` (`rest`), `app` (`api`); repeatable |
| `@GRPC` | constructor with one default `@Provide` | `register` (`pkg.RegisterXServer`, required), `server` (`grpc`), `app` |
| `@MCP` | `func(context.Context, *mcp.CallToolRequest, In) (*mcp.CallToolResult, Out, error)`, func or method | `name` (snake case of the handler), `server` (`mcp`), `app` |
| `@Function` | `func(context.Context, cloudevents.Event) (T, error)` | `adapter` (`cloudevents`, `kafka`, `nats`, `pubsub`), `app`; one per app |
| `@Middleware` | constructor with one `@Provide` | plugin names, positional |
| `@Default` | constructor with one `@Provide` of a value another constructor also provides | -- |
| `@Config` | exported struct outside `main`, one per package | -- (field tags `default`, `desc`, `hide`, `config`) |

A method handler needs its receiver provided by a default `@Provide`. A
server other than `rest`/`grpc`/`mcp` is configured under
`<app>.server.<name>`; one server name serves one kind of door. Server plugins
are a `[]boostecho.Plugin` / `[]server.Plugin` (gRPC or MCP) provided without
`name` (default server) or with `name=<server>`.

## `@MCP` -- a handler as an MCP tool

```go
// internal/app/api/mcp/handler/stock/checker/handler.go
// New provides the handler.
// @Provide(index=0)
func New(svc checker.Service) *Handler { return &Handler{svc: svc} }

// CheckStock tells whether an item can be ordered.
// @MCP
func (h *Handler) CheckStock(ctx context.Context, req *mcp.CallToolRequest, in Input) (*mcp.CallToolResult, Output, error) { ... }
```

- The handler is a go-sdk `mcp.ToolHandlerFor[In, Out]`; the door calls
  `mcp.AddTool` on the boost MCP server, which infers the input/output
  schemas from `In`/`Out` and fills the result from `Out` (a nil
  `*mcp.CallToolResult` is fine).
- Tool name: `name`, default the handler name in snake case
  (`check_stock`); letters, digits, `_`, `-`, `.`, up to 128. Description:
  the handler's doc comment without its leading name.
- `mcp` uses the shipped fx module (`boost.factory.mcp.server`); another
  name is `<app>.server.<name>` with the `[]server.Plugin` named after it.
- The handler is the app layer and calls the service; the service never
  imports `mcp`. Generation fails on a tool name twice in one server or an
  invalid name.

## `@Middleware` -- plugins around every method of a service

```go
// domain/service/stock/reserver/service.go
type Service interface {
	Reserve(ctx context.Context, sku string) error
}

// domain/service/stock/reserver/local/service.go
// New provides the stock reserver.
// @Provide(index=0)
// @Middleware(log, prometheus)
func New(repo stock.Repository) reserver.Service { return &service{repo: repo} }

func (s *service) Reserve(ctx context.Context, sku string) error {
	return s.repo.Take(ctx, sku) // plain body: no wrapper here
}
```

| Name | Plugin (`github.com/xgodev/boost/factory/local/extra/middleware/plugins/...`) |
|---|---|
| `log` | `local/wrapper/log` |
| `hystrix` | `contrib/afex/hystrix-go/v0` |
| `datadog` | `contrib/datadog/dd-trace-go/v1` |
| `prometheus` | `contrib/prometheus/client_golang/v1` |

- The first name is the outermost. At least one, no duplicates.
- The provided result is an exported, non-generic interface (LAW 22's shape).
  Every method, embedded ones included, takes `context.Context` first,
  returns `error`, `(R, error)` or `R`, and uses only exported types.
- builder generates a decorator and applies it with a root `fx.Decorate`:
  every consumer in the app receives it. `@Provide(name=x)` keeps the name;
  `group` is rejected.
- Wrapper name per method: `<package>.<interface>.<method>`, lowercased
  (`reserver.service.reserve`) -- the hystrix command, span and metric name.
  Config only turns a plugin off:
  `boost.factory.local.extra.middleware.plugins.<plugin>.<name>.enabled`
  (default `true`).
- On a member of an implementation set (`@Default` below) the decorator
  applies only when that member is the chosen one.
- Not supported: `cache`, `fallback`, different plugins per method. Those
  stay hand-built (`references/extra/middleware.md`).

## `@Default` -- implementation switch by config

```go
// internal/pkg/domain/service/price/quoter/service.go
type Service interface {
	Quote(ctx context.Context, sku string) (float64, error)
}

// internal/pkg/domain/service/price/quoter/local/service.go
// @Provide(index=0)
// @Default
func New() quoter.Service { return &service{} }

// internal/pkg/client/price/quoter/resty/client.go
// @Provide(index=0)
func New(c *resty.Client) quoter.Service { return &client{http: c} }
```

- Two or more `@Provide` of the same value (type and `name`, no `group`)
  with exactly one `@Default` form an implementation set. The
  implementation's name is its package name (`local`, `resty`).
- Key: the type's package path relative to the Go module, in dots, plus
  `implementation` (`internal.pkg.domain.service.price.quoter.implementation`,
  env `INTERNAL_PKG_DOMAIN_SERVICE_PRICE_QUOTER_IMPLEMENTATION`); a named value adds its
  name before `implementation`; a type outside the module uses its full
  import path. Default: the `@Default` package. The generated file registers
  the key.
- inject writes `gen/implementation/<type import path>/<type>_implementation.go`:
  `<Type>ImplementationModule()` includes only the chosen member's module, so
  the others and their dependencies (HTTP client, database) are never built;
  `<Type>Implementation()` returns the chosen name. Consumers and
  `gen.Module()` include the switch. An unknown name fails the boot with
  `NotValid` naming key, value and valid names -- never a fallback.
- Generation fails on: two providers of the value without `@Default`
  (AlreadyExists), two `@Default`, `@Default` without exactly one `@Provide`
  / on a group / with `@Invoke` / without another implementation, members in
  packages with the same name, members returning different types, a consumer
  of the set in a member's package, two sets with the same key.
- A member is never a `@REST`/`@Function` receiver nor a `@GRPC`
  constructor: serve the door from a type that receives the chosen
  interface.
- `@Default` marks the default *implementation*; a `@Provide` without `name`
  is the default *provider* -- different things.

## `@Config` -- settings from a struct

```go
// internal/pkg/client/price/quoter/resty/options.go -- no wrapper/config import
// @Config
type Options struct {
	BaseURL string        `default:"http://localhost" desc:"quote API base URL"`
	Timeout time.Duration `default:"2s" desc:"call timeout"`
	Token   string        `hide:"true" desc:"API token"`
}

// internal/pkg/client/price/quoter/resty/client.go
// @Provide(index=0)
func New(o *Options) quoter.Service { ... }
```

- inject writes `gen/<import path>/options_module.go`: one
  `config.Add(optionsRoot+".baseUrl", "http://localhost", "quote API base URL")`
  per field in `init()`, its env var in a comment above it, and
  `OptionsModule()` providing `*resty.Options` from
  `config.NewOptionsWithPath`. Every constructor receiving `*Options` (same
  package or `*resty.Options`) includes it; so does `gen.Module()`.
- `@Config` takes no keys; exported struct, outside `main`, at most one per
  package. Every exported field is a key unless tagged `config:"-"`.
- Types: `string`, `bool`, `int`..`int64`, `uint`..`uint64`, `float32`,
  `float64`, `time.Duration`, `[]string` -- nothing else (no nested struct,
  map, pointer or named type).
- Tags: `desc` required; `default` optional (zero value without it), parsed
  at generation (`2s`, `true`, `a,b` for `[]string`); `hide:"true"` adds
  `config.WithHide()` (secrets); `config:"name"` renames the segment
  (lowerCamel).
- Key: the package path relative to the Go module in dots, plus the field's
  words in lowerCamel: `internal.pkg.client.price.quoter.resty.baseUrl`, env
  `INTERNAL_PKG_CLIENT_PRICE_QUOTER_RESTY_BASE__URL`. A `[]string` env value is
  split by commas (`..._SOLD__OUT=book,pen`).
- Generation fails on: a missing `desc`, a default that does not parse, an
  unsupported type, an embedded field, a tagged unexported field, a second
  `@Config` in the package, a function also providing `*Options`, and two
  keys equal or one the parent of the other (configs and implementation
  keys alike).

## Factory clients -- `@Inject(..., plugins=[...])`

```go
// internal/pkg/client/price/quoter/resty/client.go -- no factory module by hand
// @Provide(index=0)
// @Inject(index=0, name=quote, plugins=[otel, prometheus])
func New(c *resty.Client) quoter.Service { ... }
```

- inject writes `gen/client/github.com/go-resty/resty/v2/quote_client.go`:
  `init()` runs the factory's and each plugin's `ConfigAdd(path)`;
  `QuoteClientModule()` provides `*resty.Client` `name:"quote"`, built by
  `factory.NewClientWithConfigPath(ctx, root, otel.Register, ...)`. Every
  consumer's module includes it; so does `gen.Module()`. fx builds it only
  when a consumer is built (an implementation config did not choose never
  builds its client).
- Clients and plugin names:

| Client type | Plugins |
|---|---|
| `*resty.Client` | `log`, `health`, `otel`, `datadog`, `prometheus`, `retry`, `requestid` |
| `*redis.Client`, `*redis.ClusterClient` | `health`, `otel`, `datadog`, `prometheus` |
| `*mongo.Conn` (boost mongo factory v1/v2) | `health`, `otel`, `datadog`, `prometheus` |

- One client per `name`, each with its own config: `name=quote` lives under
  `boost.factory.resty.clients.quote.*` (env
  `BOOST_FACTORY_RESTY_CLIENTS_QUOTE_HOST`); no `name` is the factory's
  default client (`boost.factory.resty.*`). Names are lowerCamel. Two
  services calling two APIs are two names, never one shared client.
- The annotation chooses the plugins; config only turns one off
  (`...clients.quote.plugins.otel.enabled`, default `true`). Pick ONE tracing
  vendor in the list (LAW 35).
- Consumers of one name share the client; each may repeat `plugins` only
  with the same list, or omit it.
- An app `@Provide` of the same type and name wins and nothing is
  generated; a client param without `@Inject` is left to the app.
- Generation fails on: `plugins` on a non-client param, on an app-provided
  client, with `group` or on `@Provide`; an unknown or repeated plugin;
  different lists for one client; a non-lowerCamel name.
- `*sql.DB` (pgx, godror) and other factories are not generated: keep the
  hand-written `lib/boost/factory/<factory>/module.go` (`fx/modules.md`).

## Red flags

| Red flag | Fix |
|---|---|
| `wrapper.Exec(ctx, ...)` / `middleware.New*Wrapper` written in a service method | `@Middleware(...)` on the constructor; the method body stays plain |
| `mcp.AddTool(srv.Instance(), ...)` written by hand in a builder app | `@MCP` on the handler |
| Hand-written fx module, door module or `cmd/<app>/main.go` in a builder app | Annotate and `go generate ./...`; edit the source, never `gen/` |
| A new app started with hand-written fx modules | A new app is a builder app from line one -- layout in `../../index.md` (Architecture) |
| `service/reservestock`, `service/reserve`, `handler/reservestock` | `<entity>/<agent>`: `service/stock/reserver`, `handler/stock/reserver` (`creator`, `finder`, `updater`, `remover`) |
| Hand-written switch module (`sync.Once` + `switch` on an `implementation` key) in a builder app | `@Provide(index=0)` on each implementation, `@Default` on the one wired when the key is unset |
| `AlreadyExists` for two `@Provide` of the same value | They are implementations: mark one `@Default`; otherwise give each a `name` |
| Hand-written `lib/boost/factory/<resty, redis, mongo>/module.go` in a builder app | `@Inject(index=N, name=<api>, plugins=[...])` on the client param |
| One resty client shared by services calling different APIs | One `name` per API: each gets its own `...clients.<name>.host` |
| `otel` and `datadog` both in a client's `plugins` | One tracing vendor (LAW 35) |
| Hand-written `config.go` (`config.Add` in `init()` + `NewOptions`) in a builder app | A `@Config` struct with `default`/`desc` tags; the constructor receives `*Options` |
| Knobs of an in-domain implementation passed through a hand-written fx module | A `@Config` struct in its own package -- it imports no config (LAW 20 holds) |
| `@Middleware` on a constructor returning `*struct` | Return the interface (LAW 22) |
| Vendor SDK imported to trace/measure a service | The plugin name in `@Middleware`; the vendor is config (LAW 21) |
| `gen/` not regenerated after changing an annotation | `go generate ./...`; keep a test comparing `Render` output with `gen/` |
